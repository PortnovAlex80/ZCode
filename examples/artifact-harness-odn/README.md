# ОДН: пилот паспорта титульного листа

## Актуальный результат: Word

Реальное поручение ОДН требует `.docx` по образцу существующего проекта.
MD/TXT ниже остаются учебной проверкой контекста; готовым титулом они не являются.
Паспорт документа должен ссылаться на реальный Word-шаблон, JSON-запрос и навык
создания DOCX. Обсуждение открывается существующим значком **Discussions**, без выделения текста.

Перенесите `tools/build_title_docx.py` в рабочий проект и подготовьте запрос:

```json
{
  "version": 1,
  "template": "templates/title-source.docx",
  "templateSha256": "<точный SHA-256 шаблона, 64 строчных hex-символа>",
  "output": "exports/title.docx",
  "replacements": [
    {"find": "СТАРЫЙ ШИФР", "replace": "НОВЫЙ ШИФР", "expectedOccurrences": 2}
  ],
  "requiredText": ["НОВЫЙ ШИФР"]
}
```

Команда из корня проекта: `python tools/build_title_docx.py --root . --request title-request.json`.
Python 3.10+; сторонние библиотеки не нужны. Без замен получается точная копия
образца с его историческими реквизитами. Для нового выпуска задайте подтверждённые
замены и новое имя результата. Программа создаёт DOCX и `.receipt.json`, проверяет
хэши и отказывается затирать изменённый автором файл. После замены реквизитов
проверьте страницы в Word: длина текста может повлиять на переносы.

Реальные исходники и реквизиты находятся только в локальном проекте ОДН.
Подробный контракт: [ODN-WORD-TITLE-PILOT.md](../../docs/spec-harness/ODN-WORD-TITLE-PILOT.md).

## Первоначальная учебная проверка MD/TXT

Это учебные данные для проверки работы ZCode Harness, не проектное решение.
Оригинальные документы CONSS/ОДН не изменяются. Здесь проверяются инструкции,
источники и оформление содержания; соответствие стандарту и PDF-вёрстка не заявлены.

1. Откройте эту папку как проект ZCode (а не весь репозиторий форка).
2. Откройте `docs/title-sheet.md` в панели документов.
3. В шапке документа нажмите **Metadata**: в редакторе можно выбрать сам файл,
   папку `docs` или корень проекта. Измените реквизиты в `project-data.txt`.
4. Нажмите существующий значок облачка **Discussions** у документа: откроется
   чат этого файла. Выделять текст не требуется.
   В меню **Context** включите
   использование метаданных и откройте просмотр собранного контекста.
5. Проверьте три источника: `.`, `docs`, `docs/title-sheet.md`. История другого
   проектного чата не должна появиться. Модель и уровень размышления выбираются штатно.
6. В поле **Ask ZCode anything** в чате документа отправьте: «Оформи титульный лист по исходным данным и шаблону. Покажи, каких
   сведений не хватает. Сохрани моё примечание».
7. Сверьте документ с TXT и шаблоном. Неизвестный согласующий должен остаться
   незаполненным; в отчёте агент должен перечислить недостающие сведения.
8. Добавьте авторскую строку и измените год в TXT. Попросите обновить титул.
   Правки автора должны сохраниться, год — обновиться. Если изменить паспорт,
   следующая отправка должна получить новую редакцию контекста.

Кнопка просмотра показывает текущий паспорт. При каждой отправке он читается
повторно; ошибка чтения блокирует отправку и сохраняет черновик. Выключение
контекста прекращает добавление новых снимков, но уже отправленные инструкции
остаются в истории: для чистого опыта создайте новое обсуждение.

## Что переносится в паспорт

Назначение, источники, инструкции, ссылки на навыки, критерии готовности и шаги.
Для шага описываются вход, действие, инструмент, ожидаемый результат и поведение
при ошибке. Ссылки не означают автоматического чтения всех файлов: агент читает
нужный навык/источник через штатный инструмент.

В этом опыте transport=`file`: локальное чтение и изменение MD/TXT. Следующим
шагом получение реквизитов можно привязать к существующему MCP-инструменту
или REST-адаптеру. Поля `connection`/`operation` — логические ссылки на настройку
интеграции, не URL и не исполняемый код. Недоступное подключение агент обязан
показать, а не выдумывать инструмент. Пароли и токены в паспорт не записываются.

Здесь нет нового движка workflow: порядок шагов выполняет агент через существующие
разрешения ZCode. Экспорт PDF, расчёт опоры, MCP-подключение и автоматическое
подтверждение чеклиста не запускаются от открытия паспорта.
