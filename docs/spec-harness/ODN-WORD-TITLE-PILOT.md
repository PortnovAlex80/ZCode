# ОДН: настоящий титул Word

2026-10-15: пользователь уточнил, что ожидает DOCX по образцу реального проекта,
а не текст титула в Markdown. Предыдущий учебный MD/TXT опыт проверял контекст,
но не удовлетворял этому требованию к выходному артефакту.

## Контракт результата

MD может содержать постановку и обсуждение; выход этого поручения — настоящий
Word OOXML `.docx`. Результат связывается с реальным шаблоном, его SHA-256,
явным запросом и квитанцией. Markdown и учебный TXT не заменяют реальные реквизиты.
Неизвестные новые сведения нельзя выводить из года запуска или имён файлов.

Локальный read-only образец найден в GDesign: `docs/Записки/drive-download-20260824T094350Z-1-001/Расчеты/Титульные к РР.docx`.
Это исторический исходник, не новое согласование/подпись. Он копируется только
в рабочую папку пилота; оригинал и код GDesign/CONSS не изменяются. Реальные
документы и реквизиты не публикуются в Git форка.

## Исполнение

Сохраняется вся структура пакета Word: стили, секции, рамки, колонтитулы, картинки,
таблицы и свойства. Не пересобирать сложный титул из свободных абзацев. Проектный
инструмент `tools/build_title_docx.py` копирует OOXML-части и поддерживает только
явные проверяемые текстовые замены с ожидаемым количеством совпадений.

Запрос version=1 содержит относительные template/output, точный templateSha256,
необязательные replacements и requiredText. Без указанных новых реквизитов
сохраняются исторические данные реального образца, включая его даты/подписантов;
они не выдаются за новое подтверждение авторами. Обязательная квитанция связывает
хэш запроса, шаблона и итогового файла. Совпадающий проверенный выпуск используется
повторно, авторские изменения и неожиданный существующий файл не перезаписываются.

Паспорт Word-поручения ссылается на шаблон, JSON-запрос, навык и точную команду
штатного локального инструмента агента. Это пример реального действия через harness,
а не новый модельный клиент или workflow engine. MCP/REST при необходимости остаются
альтернативными существующими подключениями, не создаваемыми от открытия паспорта.

Проверки: синтетические OOXML fixtures для отказов/замен/сохранности частей;
реальный DOCX по локальному исходнику; независимый Word reopen/render в собственном
скрытом экземпляре/временном каталоге, проверка страниц и содержимого. Ни запуск
solver jobs, ни изменение работающих документов Office этим поручением не нужны.
