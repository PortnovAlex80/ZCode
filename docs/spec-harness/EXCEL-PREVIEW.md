# Excel: встроенная панель

Объём текущего прототипа: отдельная надстройка Excel и тестовая книга XLSX, общий UI и модель локальных обсуждений с Word, собственный SharedRuntime книги. Работающие Word и ZCODE не перезапускаются. Транспорт, модель, VBA и запись в книгу отключены.

Входы: кнопка «Панель ZCODE» на «Главная»; ПКМ ячейки → ZCODE → «Добавить в беседу» / «Обсудить отдельно»; кнопка «Взять из Excel» и «+» в панели. Контекст содержит адрес листа/диапазона, отображаемые значения и формулы. Чтение использует Excel.run и сначала проверяет размер диапазона: максимум 1000 ячеек, затем максимум 20000 символов для локальной цитаты. Несмежное выделение и слишком большой диапазон требуют выбрать меньший смежный диапазон. Панель не сканирует всю книгу автоматически.

Отдельные дискуссии сохраняют снимок выбранного диапазона и собственную историю. Общая беседа книги имеет другую историю. Переключение и удаление повторяют Word. Закрытие книги завершает временную историю. Формулы не выполняются JavaScript-кодом; показываются как текст. Манифест ReadWriteDocument нужен Excel API и управлению панелью; текущий код не вызывает операции записи.

Приёмка: реальный Excel показывает панель и пункты ПКМ; чтение тестового диапазона возвращает адрес, значения и формулы; дискуссия получает снимок; Excel не вызывает ZCODE. Проверки диапазона выполняются отдельно от ручной приёмки надстройки.

## Варианты полной интеграции

Основной адаптер — Office.js: диапазоны, формулы, листы, таблицы и диаграммы доступны через Excel JavaScript API. Панель и обработчики команд работают в едином runtime, а агент остаётся в общем ядре ZCODE через будущий транспорт. Операции записи надо оформлять отдельными типизированными командами с проверкой свежести диапазона и подтверждением пользователя; этого транспорта и применения правок в прототипе нет. [Excel add-ins overview](https://learn.microsoft.com/office/dev/add-ins/excel/excel-add-ins-overview).

VBA — дополнительный адаптер для существующих desktop-макросов и API, отсутствующих в Office.js. Использовать известные макросы по имени и явным аргументам; не превращать чат в автоматическое выполнение произвольного VBA. COM/VSTO потребует отдельного Windows-компонента, его установки и сопровождения. Не нужен для первой панели. Office Scripts подходит для самостоятельных автоматизаций и Power Automate; это отдельный механизм, а не встроенный транспорт чата. [Различия VBA и Office Scripts](https://learn.microsoft.com/en-us/office/dev/scripts/resources/vba-differences).

Приоритет: полноценный Office.js адаптер и общий транспорт → согласованное применение формул/таблиц → при наличии реального пробела отдельный VBA/COM мост. UI остаётся внутри Excel; не копируем его ленту или сетку в веб-панель.

Проверено на установленном Excel: Office.onReady подтверждает Excel, чтение A1:D4 возвращает Sheet1!A1:D4, значения и три формулы; кнопка отдельной дискуссии создаёт одну ветку; горизонтального переполнения панели нет. Microsoft-валидатор принимает manifest. Пять тестов чтения диапазона, отказа большого выделения, порядка команд и изоляции истории прошли. Фактическое нажатие ПКМ Excel отдельно пока не проверено; манифест использует ContextMenuCell и те же проверенные обработчики shared-runtime, что Word.
