## 1. Ролевой тоггл «Боковая панель»

Одна кнопка в шапке главного окна, рядом с кнопками окна.

- [ ] 1.1. Обычный режим (чат в центре): «Скрыть боковую панель» прячет панель вкладок
      (Open doc и др.), чат распахивается на всю ширину; кнопка меняется на
      «Показать боковую панель» и возвращает всё назад.
- [ ] 1.2. Режим «Документ в центре»: та же кнопка в том же месте теперь прячет чат,
      документ распахивается; возврат работает.
- [ ] 1.3. Спрятать боковую панель → свап → спрятать снова → вернуть свап: скрытое
      остаётся скрытым, роли меняются, ничего не ломается и не мигает.
- [ ] 1.4. Старых кнопок больше нет: ⤢ «Развернуть документ» в шапке документа и
      отдельная стрелка возврата чата исчезли — управляет только единый тоггл.

## 3. Обсуждение в настоящем окне рабочего стола (U-06)

Требования уточнены 2026-10-15. Базовый native detach/Return проверен;
полные условия каждого пункта сверяются отдельно. [План рефакторинга](FLOATING-WINDOWS-REFACTOR-PLAN.md).
Окна проверяются в разрешённой изолированной среде; активное приложение и платные
запросы этим чек-листом не разрешены. Стриминг/permissions сначала подаются fixture.

- [ ] 3.1. Иконка «Вынести в окно» создаёт отдельное немодальное окно ОС. Его можно
      полностью вытащить за границы документа И окна ZCODE, поверх другого приложения;
      исходный документ остаётся доступен. Окно по умолчанию поверх обычных окон.
- [ ] 3.2. Перетащить на другой монитор, включая монитор слева от основного; проверить
      масштабы 100/150/200%, размер, сворачивание и разворачивание. Заголовок, ввод,
      меню и Return доступны; границы компонента документа движение не ограничивают.
- [ ] 3.3. Написать многострочный черновик, выделить часть текста, добавить готовое
      вложение, включить поиск и прокрутить историю. Detach → Return и Detach → X
      сохраняют всё перечисленное, активное обсуждение и исходный фрагмент документа.
- [ ] 3.4. Изменить размер и положение → Return → Detach: геометрия восстановлена.
      Отключить второй монитор → открыть снова: окно и его заголовок доступны на
      оставшемся дисплее, оно не потерялось за экраном.
      Ограничение текущей реализации: сохраняются ширина/высота, координаты x/y
      не сохраняются. Восстановление позиции после отключения монитора не реализовано.
- [ ] 3.5. Во время streaming и ожидания permission/question выполнить Detach/Return.
      Сессия та же; вопрос доступен, Stop относится к тому же run, новых model requests
      и второго агента из-за перемещения не возникает.
- [ ] 3.6. Двойной клик «Вынести»: одно окно. Повторный вызов показывает существующее.
      X/Return во время открытия не оставляют две отправляющие формы или пустую область.
      Переподключение remote и переход draft → native session не меняют identity окна
      и не создают дубликат; прежнее поколение attachment больше не может отправлять.
- [ ] 3.7. Во время IME-ввода или незавершённой обработки вложения перенос явно
      отложен с причиной; исходный ввод сохранён. Завершить ввод → повторить → успешно.
- [ ] 3.8. Переключить вкладку документа/проект, раскрыть документ, сделать swap,
      открыть настройки: отдельное окно сохраняет свой workspace/документ/обсуждение.
      Изменения и несохранённый текст самого документа не теряются.
- [ ] 3.9. При ошибке открытия исходная форма остаётся рабочей. При ошибке возврата
      отдельное окно остаётся открытым с повтором операции; timeout не закрывает его.
      При sessionNotFound показано восстановление/ошибка, новая сессия молча не создаётся.
- [ ] 3.10. После имитации crash renderer восстановлена последняя подтверждённая
      revision черновика; нет ложного обещания восстановления неподтверждённых нажатий.
      При обычном X/Return сохранён весь актуальный черновик.
- [ ] 3.11. 20 циклов Detach/Return, включая X: без накопления окон/Host/attachments;
      scroll сохраняет anchor, режим following остаётся following. Результат записан
      с SHA сборки и фактически проверенными размерами истории.
- [ ] 3.12. Закрытие вкладки-источника сначала безопасно возвращает дискуссию;
      отмена сохраняет вкладку и отдельное окно. Обычный restart показывает сохранённые
      черновики inline; следующий Detach использует сохранённую геометрию.
      Ограничение текущей реализации: закрытие документа с вынесенной дискуссией
      просит сначала выполнить Return вручную; автоматический Return при закрытии
      вкладки ещё не реализован.

## 4. Чат, отцепленный от ZCode

- [ ] 4.1. Иконка «вынести в окно» на шапке чата: чат уезжает в окно ОС, таскается
      по рабочему столу и мониторам, по умолчанию поверх обычных окон; приложение
      продолжает работать. Защищённый рабочий стол/UAC не перекрывается.
- [ ] 4.2. Одновременно вынести чат и два обсуждения из разных вкладок. Все три
      окна остаются открытыми, двигаются независимо, могут находиться на разных
      мониторах. Открытие одного не возвращает другое — общего desktop PiP-слота нет.
- [ ] 4.3. Вернуть всё на места — компоновка и состояние исходные.
- [ ] 4.4. Свернуть/скрыть главное окно: отдельные окна остаются рабочими, streaming
      и permissions продолжаются. X главного окна при открытых отдельных окнах
      скрывает его, сохраняя Host; последний Return показывает главное окно.
- [ ] 4.5. Сменить проект/сессию в основном окне: вынесенный чат остаётся на исходной
      сессии. Return восстанавливает её в адресном месте без потери других вкладок.
- [ ] 4.6. Действуют все проверки сохранности 3.3, управления 3.5, ошибок 3.6–3.10
      и повторных циклов 3.11. Вынесенная и исходная копии не отправляют одновременно;
      независимые существующие document/web surfaces не отключаются новым механизмом.
- [ ] 4.7. Смена model/mode не создаёт двух владельцев execution configuration.
      Выбор, отправка, отложенный ACK и Return сохраняют один принятый commandId;
      поздний callback прежней формы не отправляет дубликат.
- [ ] 4.8. Alt+Tab/панель задач показывают понятные проект/чат/документ и значок ZCODE.
      Кнопки имеют подписи и клавиатурный доступ; новые токены не перехватывают фокус.
- [ ] 4.9. Явное «Выйти из ZCODE» следует штатному завершению приложения. X отдельного
      окна — Return, а не Stop/Delete/Quit. После завершения нет orphan окон/processes.
- [ ] 4.10. Измерены shell/content/interactive p50/p95, ввод, CPU/RSS для 0/1/3 окон
      по процедуре плана; source placeholder и скрытые окна не пересобирают тяжёлую
      presentation на каждом токене. Unit-тесты не заменяют эту GUI-проверку.
