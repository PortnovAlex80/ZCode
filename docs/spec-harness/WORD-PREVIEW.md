# Локальный preview внутри Word

Статус: историческое описание первого UI-прототипа без транспорта ZCODE; этот режим сохранён отдельно по `/demo`. Основная панель теперь имеет native transport и операции Word. Текущий объём: [DOCUMENT-HOSTS.md](DOCUMENT-HOSTS.md), [сборка и подключение](../../prototypes/document-host/README.md), [актуальная приёмка](IMPLEMENTATION-CHECKLIST.md). Ограничения и результаты ниже относятся к раннему demo, не к основной панели.

Word владеет документом. Панель читает выделение через Office.js; черновики, список демонстрационных обсуждений и сообщения находятся только в памяти страницы. Send добавляет явно демонстрационный ответ без сети и модели. Применение правок документа не реализовано. ПКМ и панель используют общий SharedRuntime 1.1: команда читает выделение до показа панели, история находится в памяти одного runtime текущего документа; закрытие документа/Word очищает её. Постоянного хранилища пока нет.

Надстройка имеет отдельный ID и manifest с ReadWriteDocument: этого требует API управления общей панелью Office; вызовов записи документа в прототипе нет. Тестовый документ и сертификаты/настройки sideload находятся вне Git. Для загрузки страницы используется официальный Office.js CDN; содержимое выделения не отправляется на сервер preview и не логируется. В прототипе отсутствуют вызовы ZCODE и провайдеров.

Экран: имя панели, индикатор «Без подключения», режим «Документ»/«Обсуждения», кнопка чтения выделения, цитата фрагмента, список локальных дискуссий с удалением, область сообщений, поле ввода и Send. Enter отправляет, Shift+Enter переносит строку. Узкая/широкая панель сохраняет доступ к composer и scroll истории.

Приёмка: Word открывает sample документ с панелью; Office.onReady подтверждает Word host; чтение выделения обновляет quote; создание/переключение/удаление локальной дискуссии и отправка работают; ответы помечены как demo; сервер не подключается к ZCODE. Проверки mock Office и фактический sideload не являются проверкой будущего SessionPane integration.

Реализация: `prototypes/word-preview`. Запуск и восстановление окружения описываются в README этого каталога. Используем Microsoft dev-certs/debugging только для HTTPS/sideload; install не меняет зависимости основного форка.

Оформление повторяет нейтральные light/dark поверхности, типографику, скругления, пузырь пользовательского сообщения и composer ZCODE. При первом открытии тема определяется темой Office; ручное переключение действует только на панель. Word сохраняет свою ленту, контекстное меню, выделение и управление документом. Модель и права не становятся фиктивными рабочими селекторами: до появления транспорта показываются «Модель не подключена» и «Только чтение».

Следующий вход: штатные команды `VersionOverrides` → `ContextMenu` → `OfficeMenu id="ContextMenuText"`. Планируются «Добавить в беседу» и «Обсудить отдельно», с открытием единой панели и чтением актуального выделения после готовности Office.js. Не подменяем меню Word и не создаём новую панель на каждое нажатие. Команды реализованы в manifest и зарегистрированы локально; фактическое отображение и нажатие «Обсудить отдельно» проверены в Word: новая ветка содержит 146 символов выделенного абзаца. Основа: [OfficeMenu](https://learn.microsoft.com/en-us/javascript/api/manifest/officemenu?view=word-js-preview).

Референс Claude Comments: список независимых веток с цитатой фрагмента и числом реплик, вход в выбранную ветку без истории общего разговора. Внешняя панель принадлежит Word, выбранная ветка использует знакомое оформление ZCODE. Запись в нативные комментарии Word пока не реализована. Текущий HTML preview повторяет оформление, но не является настоящим React SessionPane и не заявляется как полный функциональный клон.
