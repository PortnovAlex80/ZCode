# Паспорт документа: пять текстовых блоков

Актуально на 2026-10-17. Паспорт — карта сборки и проверки документа.
В интерфейсе пять многострочных полей. Пишите обычный текст или Markdown:
подробные правила, ссылки на конкретные файлы, чеклисты и примеры вызовов.
JSON используется для хранения; заполнять JSON шагов не требуется.

1. **Роль** (`role`) — назначение, место в проекте и цепочке, зависимости и
   использование результата.
2. **Шаблон** (`template`) — реальный образец, структура, разделы, поля, таблицы,
   оформление и допустимые изменения.
3. **Данные** (`data`) — источник каждого элемента, правила преобразования,
   действия при отсутствии или противоречии сведений.
4. **Сборка** (`assembly`) — порядок действий, точные команды/формы вызовов
   доступных инструментов, входы, выходы и обработка ошибок.
5. **Приёмка** (`acceptance`) — критерии содержания и оформления, чеклисты,
   доказательства готовности и непроверенные пункты.

Блоки необязательны. Подробность сохраняется: длинную инструкцию не нужно
сокращать до ключевых слов. Пустой блок не отменяет правила родительской папки.

## Как использовать

Откройте проект и документ. В **Metadata** выберите файл, родительскую папку
или корень проекта и заполните нужные блоки. Общие инструкции задавайте папке,
а особенности конкретного документа — самому файлу.

Откройте существующий значок **Discussions** без выделения текста. В **Context**
включите **Use artifact metadata**. В **Inspect artifact context…** видны
инструкции проекта, папок и файла с указанием источника каждого паспорта.
Напишите поручение в поле чата документа.

Перед каждым новым сообщением контекст перечитывается. Агент получает обычный
текст с заголовками Role / Template / Data / Assembly / Acceptance, без таблицы
полей и служебных ID. Ошибка чтения или переполнение сохраняют черновик и
блокируют отправку. Отключение прекращает добавление новых снимков; уже
отправленные инструкции остаются в истории беседы.

## Пример для Word-титула ОДН

Пример содержимого `blocks` (технические id/kind/updatedAt задаёт сервис):

```json
{
  "role": "Титульные листы расчётной записки. Результат — Word-файл для комплекта документации.",
  "template": "Образец: harness-title-pilot/templates/odn-rr-title-source.docx. Сохранить структуру, оформление, рамки, картинки и колонтитулы.",
  "data": "Явные замены и хэш образца: harness-title-pilot/word-title-request.json. Без новых подтверждённых реквизитов сохранять исторические данные образца и сообщать об этом.",
  "assembly": "Прочитать harness-title-pilot/.harness/skills/title-sheet-word.md и запрос. Из корня проекта выполнить: py -3.13 harness-title-pilot/tools/build_title_docx.py --root . --request harness-title-pilot/word-title-request.json. Проверить JSON-ответ и квитанцию. При ошибке сообщить причину; авторские правки не перезаписывать.",
  "acceptance": "Настоящий DOCX открывается Word. Реквизиты соответствуют запросу. Оформление и страницы проверены. Квитанция связывает шаблон, запрос и результат. Пользователь получил ссылку на DOCX; невыполненные проверки перечислены."
}
```

Команда относится к уже подготовленному локальному пилоту. Наличие описания не
устанавливает Python/Word и не создаёт MCP/REST-подключения. Паспорта не выполняют
команды автоматически, не расширяют права инструментов и не читают все ссылки
целиком. Критерии приёмки остаются инструкциями, пока проверка не выполнена.

## Старые паспорта

Прежние поля назначения, источников, навыков, чеклиста и шагов читаются и
показываются в пяти блоках без записи на диск. Все известные детали шагов,
включая инструмент, вход, результат и поведение при ошибке, сохраняются в тексте.
Шаблон автоматически не угадывается — его можно указать явно.

При сохранении запись становится пятью блоками, а хранилище — версии 2.
Неотредактированные старые записи продолжают читаться. Старое приложение
откажется редактировать такое хранилище, что защищает новые блоки от потери.
Перенос файла отдельно от `.harness/project.json` не переносит паспорт.
